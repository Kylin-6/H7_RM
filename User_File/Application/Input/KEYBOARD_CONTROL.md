# 老步兵键鼠控制

配套固件为「老步兵云台」的 GimbalBoard（Pitch、发射、UART7 接收）与「老步兵测试」的 ChassisBoard（四轮、Yaw）。SingleBoard 保持原模板。键鼠 Pitch 采用现有标定等效拆分的位置/速度串级，保留力矩限幅和 2 s 使能延迟；键鼠在 Input 中独立整形，遥控保留原 S 曲线。输入优化不能据此判断云台闭环滞后已解决。

## 知识库键位

| 输入 | 行为 |
| --- | --- |
| W / S | 前进 / 后退；同时按下抵消 |
| A / D | 左移 / 右移；同时按下抵消 |
| Q / E 按住 | 正 / 反向小陀螺；同时按下停止自转且不跟随 |
| Q / E 都松开 | 恢复普通跟随（相对 Yaw 反馈有效时） |
| Shift 按住 | 加速，松开恢复普通速度 |
| 鼠标 X / Y | Yaw / Pitch |
| 鼠标左键 | 释放短按单发；长按连发，释放停止连发 |
| Ctrl | 单独按下不切换跟随 |

Ctrl+Shift 组合优先：组合中的 WASD/Q/E 不产生平移、自转或跟随修正，鼠标仍可控制云台。B 爆发、V 能量机关、G 掉头、右键自瞄与整车组合快捷键仅保留原键位，不执行功能，也不映射为其他动作。完整 16 位键盘位图仍被转发。

平移由云台第一人称坐标旋转到底盘坐标，使用当前 Yaw 正前方标定与跟随符号。相对 Yaw 反馈不可用时无法保证方向，平移保持零，等待反馈；自转仍按 Q/E 意图生成。键鼠平移和旋转在 Input 中完成整形，机构侧仅执行运动学和现有单轮限幅。相对 Yaw 失效立即清除平移整形状态，恢复从零起步。

## 参数归属和量纲

| 目标 | 参数与换算 |
| --- | --- |
| Pitch | `Gimbal_Config.h`：原始鼠标限幅 ±500，完整计数 × `keyboard_pitch_rad_per_count=-0.00025 rad/count`，不再 `/5×5` 丢弃细瞄输入；每新 UART 帧只累加一次，不乘控制周期。±500 对应 ∓0.125 rad/帧，按 30 Hz 换算目标累计速率约 ∓3.75 rad/s；角度限位 −40°～+15°，机构目标斜坡与鼠标速度前馈仍限幅 3 rad/s；键鼠使用位置外环＋速度内环，松手保持角度 |
| Yaw | 云台只限幅原始 X 至 ±1000 并累计；底盘 `Chassis_Config.h` 的 `keyboard_yaw_rad_per_count=-0.000416667 rad/count`，较上一版灵敏度提高 25%，每段累计计数差只消费一次。满输入约 ∓0.416667 rad/帧，30 Hz 下目标累计速率约 ∓12.5 rad/s；生成 INS 绝对目标并复用位置闭环，不经过摇杆速度积分，电机总速度上限仍为 15 rad/s |
| 平移 | 对应遥控 CH7 第一 / 第二档：当前轴上限 ×普通比例 0.3 / Shift 比例 0.6，当前抽象目标模长 9 / 18；WASD 先归一化，直行与斜行同速，松开 Shift 恢复第一档 |
| 自转 | 当前旋转上限 ×0.2，Shift 再乘知识库倍率 1.5，当前 ±10 / ±15 |
| 发射 | `Shoot_Config.h`：键鼠长按 150 ms；小于 150 ms 的释放产生 ShootOnce，达到阈值提交 BURST，释放提交 STOP；原遥控开关仍用 300 ms |
| 摩擦轮 | 复用 Shoot 的 −25 / +25 rad/s、达速检查、热量、卡弹和 300 ms 延时停轮 |
| 拨弹盘 | 4500 rpm 转子速度 ×2π/60/减速比 36 = 13.08997 rad/s 输出轴速度；遥控波轮也引用这份换算 |

底盘抽象速度没有实测 m/s 标定，仍复用现有 `*_ToSi/FromSi` 在框架仲裁边界归一化，不把 9/18 解释成 m/s。参数集中于对应 Application 配置，输入层不重新标定电机。

## 键鼠驾驶整形

底盘 `Class_KeyboardChassis` 由 ControlTask 单独持有；原始按键、二维归一化意图、平移/旋转目标和整形状态均归 Input。默认参数在 `Chassis_Config.h`：平移速率为最大抽象速度 /0.22 s（加速）、/0.10 s（减速）、2 倍最大速度 /0.16 s（反向）；旋转使用独立的同名时间参数。当前对应 136.36 /300 /375 与 227.27 /500 /625 抽象速度每秒。反向锁存保持到新目标到达，改变按键方向或释放时取消。

二维平移限制速度变化向量的模，不按 X/Y 分别加速；先在第一人称坐标整形，再转为底盘坐标。旋转独立整形，随后以 `1 - keyboard_turn_speed_reduce * abs(shaped_w) / angular_velocity_max` 缩放平移目标，默认倍率 0.25。因此普通 Q 小陀螺下 W 稳态目标约 8.55，Shift 小陀螺下约 16.65；直行仍为 9/18。单次实际 dt 上限 `keyboard_max_dt_ms=10`，不补积长暂停，无输入低通或新增 jerk。

`ChassisCmd.input_shaped` 默认 false；键鼠置 true，Chassis 不重复三轴 S 曲线，保留运动学和同比单轮限幅。切换标记重置规划，遥控路径保持原实现。已整形命令由 RobotCmd 每个 1 ms 控制周期发布到本板 Topic，Chassis 仍每 2 ms 下发轮速，避免 10 ms 发布保持形成速度台阶；遥控目标仍按 10 ms 刷新。轮未就绪清整形状态但保留零目标使能流程，不积累待执行运动。

`GimbalCmd.yaw_absolute_target` 默认 false；底盘键鼠置 true，ControlYaw 使用绝对目标，遥控仍使用原速度 S 曲线与积分。键鼠没有额外鼠标速度前馈；P/I 使用回绕后的角误差，D 仅作用于实际 INS Yaw 变化，不对鼠标目标阶跃求导。沿用 Kp=3.5、Ki=0、Kd=0.3；D 按完整 INS 快照的实际接收时间间隔差分，重复样本保持该速率，首帧/恢复/断档重建基准，角差跨 ±π 回绕。源 gyro_z 当前为零，不能替代实测差分。底盘角速度补偿、±15 rad/s 总限幅、MIT 阻尼选择/变化率和力矩限幅保留；调试 `pid_rad_s` 为 P/I 与实测 D 合成后的修正。遥控继续使用原误差微分和速度积分，目标类型切换清 PID 与规划历史。

## 接收、来源和恢复

云台 UART7 当前采用 115200、8N1 测试配置，PE7 为 RX、PE8 为 TX，与老工程引脚相同，IOC 与初始化同步。用户确认使用 VT02/VT12 常规版及 2025 国赛 Client，但客户端年份不能单独确定发送端 UART 波特率。实机在 921600 下出现接收错误及 `0x80` 乱码，尚未收到合法键鼠帧，因此切换到 115200 做对比；该速率仍须以合法 CRC 的 `0x0304` 帧持续刷新验证，不能据此宣称全部 VT02 固件均使用 115200。官方通用协议 V1.9 的图传链路为 921600，旧版 V1.7 为 115200，需结合实际发送端固件核对。参见 [官方串口协议下载](https://www.robomaster.com/en-US/resource/pages/announcement/1768)。

GimbalBoard 使用独立的 `vtm_legacy.c/.h`，保留 `vtm_26.c/.h` 给新图传 VT03/VT13 的 A9 53 协议。Legacy 的静态 255 字节缓冲跨 UART DMA chunk 拼帧，复用官方 CRC8/CRC16；CRC 失败逐字节重同步，拒绝超长声明，不动态分配或增加任务。`VTM_Legacy_ReadKeyboardSnapshot` 保留非消费快照接口；`VTM_Legacy_TakeKeyboardBatch` 在恢复 PRIMASK 的短临界区一次取出最多 16 帧与最新快照、实际接收时间及溢出计数。容量满后丢弃不完整动作批次；Input 撤销许可、清动作，必须等待后续新帧才恢复。

VT02/VT12 键鼠使用 A5 帧：5 字节帧头（小端载荷长度、序号、CRC8）、2 字节小端命令 0x0304、12 字节载荷、2 字节 CRC16，总计 21 字节。载荷 byte0～5 为小端 int16 鼠标 X/Y/Z，byte6/7 为左右键（0/1），byte8～9 为小端完整 uint16 键盘，byte10～11 保留。键盘位序 W/S/A/D/Shift/Ctrl/Q/E/R/F/G/Z/X/C/V/B 为 bit0～15。官方发送频率为 30 Hz。仅合法 0x0304 更新键鼠实际接收 ms、本地递增序号及帧头序号；其他合法图传帧只更新链路诊断，不续期键鼠。

遥控器有健康 SBUS 帧时，CH5 中心化值 <0 选择键鼠，其余档位选择遥控；CH7 速度、CH8 跟随保持原规则。SBUS 健康要求帧年龄 ≤50 ms、无 frame_lost/failsafe；上电、切档或恢复后仍须连续健康 200 ms 才授予 SBUS 所选来源许可。

SBUS 尚未收到帧、年龄 >50 ms 或报告 frame_lost/failsafe 时，底盘自动选择键鼠候选，不沿用最后一帧 CH5 或摇杆。底盘 0x065 发送键鼠模式、候选许可和零遥控通道；云台仍须收到新鲜合法 UART7 键鼠帧（≤200 ms）、有效 INS 和 ≤50 ms 的 0x065，才发布获许可的键鼠 0x066。底盘最终仍核对本地来源与 ≤50 ms 的 0x066 模式/许可一致；仅遥控失联不能自行驱动。键鼠也失联则停机，不回放旧遥控命令。遥控器重新健康后恢复 CH5 选择，并等待原 200 ms 健康确认，等待期间不自动绕过 SBUS 解锁。

图传键鼠超时由云台 `input_state.h` 中 `INPUT_KEYBOARD_MAX_AGE_MS=200` 统一用于 UART 适配和 Keyboard 仲裁；年龄 ≤200 ms 沿用键位与已累加角目标，不重复消费鼠标，201 ms 起停机。普通裁判帧不续期；SBUS、0x065、0x066 的 50 ms 保护、Pitch 使能等待及发射恢复释放门保留。VT02/VT12 没有 pause 或遥控挡位字段。

`InputState_SetPermission(permitted, require_remote)` 只由 ControlTask 调用；默认 `(true,true)` 保留原 Remote 互锁。键鼠使用底盘所选来源许可（含 SBUS 不可用时的键鼠候选）和 UART7 键鼠时效，云台同时要求新鲜有限 INS；遥控继续要求底盘下发遥控模式、许可和 50 ms 通道时效。底盘核对本地 CH5 与 0x066 模式一致，避免切档后执行旧模式。

云台顺序为 INS 桥 → KeyboardInput（模式、许可）→ RemoteInput → RobotCmd → Gimbal/Shoot；底盘为 INS 接收 → RemoteInput → KeyboardInput → RobotCmd → Chassis。设备/协议层只解析与缓存，Input 生成意图，RobotCmd 仍是唯一命令发布者。

进入键鼠、失联、切源或 Pitch 未就绪时不积累鼠标目标；从新鲜 INS 捕获当前 Pitch，在现有使能等待期间持续保持当前姿态，就绪首批只建立基准，后续新帧才累加鼠标增量。控制任务跨过接收断档后直接看到新帧，也重置目标和释放门，避免未观察到中间超时而执行旧增量。发射动作检测重置后先观察到左键或火控开关释放才接受新动作；键鼠释放门只消费就绪后的新接收帧，不用旧快照解锁。无效 Remote/Keyboard 输入保留事件序号基线，防止恢复补发旧单发；Shoot OFF 沿用现有停轮和清事件路径。

## 双板协议

两板必须使用配套协议固件；不接受旧版无许可标记的 0x065。均为 FDCAN2、标准 ID、8 字节 Classic CAN，沿用 BSP 最新值槽；提交成功只表示软件接收目标，不确认对端执行。

### 0x066：云台 → 底盘

每 10 ms 刷新，模式或许可变化立即提交；提交失败在后续控制周期重试。

| 字节 | 内容 |
| --- | --- |
| 0 | 高四位版本 2，低四位模式 0/1/2 |
| 1 | uint8 递增序号 |
| 2～3 | 大端累计鼠标 X uint16，模 65536 自然回绕 |
| 4～5 | 大端完整键盘 uint16 |
| 6 | bit0 运行许可，其余位 0 |
| 7 | 保留 0 |

停机或无许可时线上鼠标、键盘均清零；发送端内部累计计数跨停机保持，不在瞬态停机时复位，避免 STOP 帧被最新值槽覆盖后产生伪反向增量。底盘检查总线、ID、精确长度、版本、挡位、保留位及安全帧清零规则。版本 1 和 2 不混用，必须配套更新两板。首次收到前仍采用原遥控；收到后依帧模式运行，>50 ms 无新有效序号停机，不自动回退。

底盘用相邻有效累计值的模差（映射到 −32768～32767）生成 Yaw 增量，重复周期刷新不重复消费，中间 CAN 帧丢失保留累计量。首次接收、切源、超过 50 ms 的接收断档及 Yaw 未就绪时仅捕获计数与新鲜 INS 绝对 Yaw 基准。基准捕获后的每 count 按 Application 灵敏度和现有安装方向换算。累计值不是速度，不能再按 1 kHz 或 2 ms 周期积分。

### 0x065：底盘 → 云台

原周期 2 ms 保持。byte0～1 火控、byte2～3 波轮、byte4～5 Pitch，均为大端 int16；byte6 高四位版本 1、bit0 为所选来源的健康许可、bit1～2 为模式 0/1/2、bit3 为 0；byte7 为递增 uint8 序号。健康 SBUS 按 CH5 和 200 ms 恢复条件授予所选来源许可；SBUS 不可用时改为键鼠候选许可，由云台再检查 UART 时效和 INS。仅已许可的遥控档携带三个通道，键鼠档、停机或未解锁时通道全零。云台用模式区分键鼠选择和零摇杆，用实际接收时间仲裁，不在 1 kHz 轮询时刷新时间戳。

两种协议的序号均只接受向前差值 1～127，255→0 合法，重复或回退不刷新业务快照。合法重复帧只更新链路流量基准；合法流量中断 >50 ms 后允许重建序号基准，以支持对端重启。非法帧不更新基准。协议没有会话号，间隔后的合法旧帧与重启首帧不可区分；当前不提供会话防重放。0x070/0x075 和 INS 回传 0x143/0x144 保持现有协议。

## 验证

接收快照必须先于本周期 `HAL_GetTick()` 读取。若先读时钟，再被 UART/CAN 接收中断抢占，跨毫秒的新帧时间可能大于旧的本周期时间；无符号年龄计算会误判失联，触发 Pitch 失能和 2 s 重新使能等待，并可能下发底盘停机帧。云台键鼠、遥控转发和底盘键鼠适配均按先快照、后时钟执行；快照时序修复不改变超时策略，图传键鼠现按用户要求使用 200 ms，板间链路仍为 50 ms。

此前快照时序修复曾通过跨 tick 误停机复现与边界回归；本次逐帧消费与整形的检查项目见下文。主机回归不代替实机卡顿时的同步采样和复验。蓝灯慢闪表示启动或等待使能，常亮表示未获许可；颜色本身不能证明主控崩溃。

云台 `Keyboard_Input_Debug` 仅由 ControlTask 写入，保存当前模式、许可、帧年龄、序号、INS 有效性及 Gimbal 状态。`stop_count` 在已许可键鼠退出时递增，`stops[(stop_count-1)%8]` 为最近一条，环形保留最近 8 条；记录本地毫秒、原因位图、当时键鼠帧年龄和序号。原因 bit0 为主动切回遥控，bit1 为 0x065 接收源许可失效或停机，bit2 为键鼠无帧/超过 200 ms，bit3 为 INS 无效，可同时置位。调试器运行中读取不是原子快照，应检查 `stop_count` 是否在读取期间变化；记录不参与控制，不代表电机已经执行停机，也不记录 Gimbal 内部单独发生的电机故障。新增 bit4 为接收队列溢出；`reset_reason` 复用 bit0～4，并以 bit5 表示未 READY。`consumed_sequence` 表示已处理或丢弃的最后队列帧，`pitch_delta_rad` 为本批输入增量和，`pitch_target_rad` 为限位后的绝对目标，`yaw_counts` 为跨板累计值，`overflow_count` 为 Device 累计溢出次数。实机仍卡顿时先读取历史并与 `Gimbal_Debug`、`Diagnostics_LED_State`、UART 错误/重启计数核对，200 ms 是用户指定的图传容差，尚不能据此认定实机卡顿原因或已经修复。

底盘 `Keyboard_Chassis_Debug` 提供原始帧序号/累计计数、二维意图、目标与整形后的三轴抽象速度、Yaw 增量/绝对目标；`reset_reason` 的 bit0 为切源/许可/接收断档，bit1 为轮未就绪，bit2 为相对 Yaw 不可用，bit3 为 INS 无效。调试字段由 ControlTask 唯一写入，运行中跨字段读取非原子，不参与控制。

### 鼠标 Yaw 转向冲击回归
