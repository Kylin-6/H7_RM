# 老步兵发射应用

Shoot 与其他板型共用 `Shoot_Init` / `Shoot_Update`、Topic 命令及 100 Hz 反馈入口。
设备及状态只在 Shoot.cpp 的私有 Context 内；板型差异用于装配实际电机，机构参数
集中在 [Shoot_Config.h](Shoot_Config.h)，接线集中在 BoardConfig。

- DM3519 摩擦轮在 FDCAN1：左节点 0x07 / 反馈 0x027，右节点 0x08 / 反馈 0x028，
  电机端预先配置速度模式，目标分别 -25 / +25 rad/s。
- M2006 拨弹盘在 FDCAN2：ID 1，减速比 36，每弹 2π/7 rad。速度/角度环沿用原标定。
- 旧底盘 0x065 帧仍由 Device 解码；输入层执行开关滞回和长短按识别。
  短按释放（小于 300 ms）产生 ShootOnce 序号，RobotCmd 经来源仲裁去重后入队；
  长按（达到 300 ms）提交持续 BURST，速度来自波轮。
- 健康输入的 `ShootMode::ON` 表示安全许可，松扳机提交 STOP / friction OFF，
  不取消刚释放的单发。失联或仲裁撤销才提交 OFF，同周期停止所有输出并清除排队动作。
- STOP 每周期至多消费一个单发/三连发事件，角目标累加；BURST / REVERSE 优先并取消排队动作。
  事件队列满时拒绝并计数，不在之后补射。
- 单发需要摩擦轮达到速度容差 ±1 rad/s、拨弹盘反馈在线及热量许可；
  拨弹 1 s 超时从实际开始角度控制计时，不包含等待摩擦轮就绪及卡弹回退的时间。到位/超时后
  锁住实际角度 100 ms，再保持摩擦轮 300 ms。连发退出先以零速度闭环制动，
  输出轴速度 ≤0.2 rad/s 后才消费单发事件，首发从停稳后的实际角度追加一个弹位，
  并清除连发遗留的 PID 积分；摩擦轮随后延时停轮。
- 卡弹确认 300 ms 后，从实际位置回退半个弹位（约 25.71°）；编码器误差 ≤2°
  即结束回退，单发继续原目标、连发恢复速度。200 ms 仅作为回退超时上限；
  超时未到位锁存拨弹停止并清除事件，`ShootMode::OFF` 后才复位，持续扳机不能自动重试。
  回退期间暂停单发超时，保留热量估计；
  状态时间按 HAL tick 差维护，不按控制调用次数计时；电机掉线/故障取消旧动作，
  恢复只接受新的事件。热量估计并非裁判系统的真实热量反馈。
- Enable/Disable 请求由驱动维护，初始化保持失能，不再在应用中重复维护协议重试定时器。
  CAN 提交失败不能等同于发送成功，周期目标下一拍提交最新值。

保留 USART1 的 24 路 JustFloat 诊断布局，便于实车对比。`ShootFeedback.enabled` 需安全许可
有效且三台电机 ready，初始化成功不再等同于机构已使能。

迁移后的短按、长按、队列积压、失联停止、单发到位、卡弹回退与热量互锁仍需实机复验。
