# 老步兵底盘板应用

上电后蜂鸣器播放一次用户旋律，接入方式见 [蜂鸣器旋律](../BuzzerMusic/README.md)。

ChassisBoard 固件承载老步兵底盘板：四路 DM 麦轮、一路挂在本板的 Yaw DM 电机、
SBUS 遥控接收，并经 FDCAN2 向云台板下发 0x065/0x070/0x075 下行帧。云台 Pitch 与
发射机构在云台板固件上，不在本模块内。

同一份 `Chassis.cpp` 还保留框架四舵轮 AGV 实现（`CHASSIS`），当前默认预设不编译；
本实现即 ChassisBoard 构建编入的底盘应用，见 [Application 指南](../README.md)。

底盘调试固件关闭 BMI088 加热：初始化不启动 TIM3 CH4 PWM，温度采样、
加速度/陀螺仪采集和姿态解算继续运行。需重新烧录才能在板上生效。

底盘 OSPI2 的 W25Q64（8 MiB）按 100 Hz 保存运动与 Yaw 故障数据，
由 StorageTask 写入，不在控制周期等待 Flash；格式、状态和导出方法见
[Flash 故障记录](FlashLog/README.md)。

## 控制契约

CH4 Yaw 摇杆保留 3% 中心死区，三次指数曲线系数为 0.30，
加快微调段速度增长；当前摇杆满杆速度上限为 8 rad/s，半杆目标约 2.99 rad/s。
摇杆速度先做 S 曲线规划，积分为 IMU Yaw 角目标并叠加位置误差修正与底盘角速度前馈，
由 IMU 位置误差反馈抵消底盘转动，最后按总速度上限 15 rad/s 限幅，
降低摇杆上限不会同步压低位置修正上限；合成需求超过 15 rad/s 时仍会饱和。
实际响应还受速率规划影响。此调整尚待实车验证。

CH7 使用固定三挡速度：通道 < -392 为低挡 30%，[-392, +392] 为中挡 60%，
> +392 为高挡 100%。三挡同时缩放平移和手动自转上限，最低挡不再停车；
停车使用平移摇杆回中、CH10 回到停止区或 CH5 手动保护。Yaw 摇杆速度不受 CH7 影响。

CH10 小陀螺自转边界为减去中位后的 +350：通道低于 +350 时，从边界零速
按指数曲线连续增加负方向自转速度，-784 达到原来的档位旋转上限；+350 及以上
交回 CH8 跟随开关；CH5 用于手动失联保护。CH10 回到中位 0 仍有自转目标，
停止手动自转需推回 +350 及以上（跟随开关开启时仍可能跟随转动）。此调整尚待实车验证。

底盘正面跟随云台：CH10 ≥ +350、CH8 > 0 且 Yaw 反馈新鲜、已就绪、角度有限时，
计算 `forward_error = wrap(yaw_encoder - π)`（范围 `[-π, π)`）。
跟随角度死区为 ±2°（`follow_deadband_rad`，内部 rad），区内修正为零；区外
先从偏差幅值扣除 2°，再以原符号生成 `follow_rotation = -follow_error * 8`，
保持死区边界连续，并按实车反馈反转修正方向。
修正单独限幅到 `min(速度档旋转上限, follow_rotation_max)`，当前跟随上限为
5（抽象速度单位），即原最大旋转上限 50 的 10%；小陀螺不受此独立上限影响。
手动旋转与跟随修正分开计算，合成后统一按
速度档旋转上限限幅，再进入底盘 W 轴 S 曲线和麦轮混合。CH10 自转区优先关闭修正，
退出后恢复跟随；CH8 关闭或反馈失效时修正为零，反馈失效时也不做平移坐标旋转。
沿用现有机械零位与方向约定，实车需低速确认对齐方向。
主机使用实际输入计算代码检查了角度回绕、反转后的方向模型下的偏差收敛、CH10
+349/+350/+351 切换、CH8 开关、失效/非有限角度反馈、原零速度档和饱和限幅（此为三挡改动前的检查）；
另检查了死区边界连续、跟随独立限幅及 CH5 不再控制跟随；小陀螺输出保持原映射。
此验证不替代实车方向与机械零位检查。

`ChassisCmd` 由 RobotCmd 每 10 ms 刷新，本模块按 100 ms 时效读取，Topic 过期即按
`ZERO_FORCE` 处理。`GimbalCmd`（Yaw 轴）沿用框架云台命令的语义：只在目标变化或安全
撤销时发布，因此按最新值读取、不判时效，否则摇杆保持不动会被误判为过期；遥控失联时
RobotCmd 会把命令撤销为 `DISABLED`。

- 底盘平移：底盘坐标命令 → 还原云台坐标 → X/Y S 曲线 → 按当前 Yaw 偏差旋转 → 四轮组合。
  无有效 Yaw 反馈时在底盘坐标规划；坐标有效性切换时清零平移规划，避免旧坐标残留。
- 底盘旋转：W 轴仍独立做 S 曲线。四轮超限时同比缩放到单轮上限 30，
  保持平移/旋转比例，避免逐轮截断改变行进方向。该修改尚待实车小陀螺行进验证。
  `w0 = y + x + w`、`w1 = y - x + w`、`w2 = -y - x + w`、`w3 = x - y + w` → 单轮限幅 →
  `SetSpeed()`。组合式不做轮距与半径换算，与老工程一致。
- Yaw：摇杆速度（±8 rad/s）→ 框架 `Class_Trajectory` 速度 S 曲线 → 积分为云台 IMU
  Yaw 角目标 → 位置 PID 修正与摇杆速度、本板角速度前馈合成 → 总速度限幅（±15 rad/s）→ 自适应阻尼与
  力矩前馈（逐周期限速）→ `SetMIT(0, speed, 0, kd, torque_ff)`。
  IMU 位置外环公式、方向配置与恢复行为见下方。
- 底盘 X/Y/W 三轴使用 `Class_Trajectory`，保留零速目标门限 0.1。
  X/Y 加速度上限 180、jerk 上限 18000；W 加速度上限 350、jerk 上限 35000，
  单位分别为抽象速度/s、抽象速度/s²，约 10 ms 建立最大加速度。
  麦轮混合后仍逐轮限幅 ±30；三轴 jerk 限制不等于混合后每个轮子的 jerk 限制。
  失能时重置三轴规划；任一轴规划失败时四轮提交零速并请求失能。
  旧三轴 `*_decel_limit`、`*_release_limit`、`*_reverse_limit` 暂不参与试验控制。
  主机验证 X/Y 0→30 约 178 ms、30→-30 约 344 ms；W 0→50 约 154 ms。
  反向、松杆、运动中改目标及速度/加速度/jerk 边界检查通过，尚未测实机与 MCU 耗时。

Yaw S 曲线只规划摇杆目标：速度上限 8 rad/s、对称加速度上限 150 rad/s²、
jerk 上限由 15000 降到 7500 rad/s³，加速度建立时间约 20 ms，柔化起转与换向；
周期 2 ms，运动中改目标从当前规划状态接续。
位置 PID 修正与底盘角速度前馈在规划之后叠加，不受摇杆零速门限、加速度与 jerk 限制；合成速度仍限幅 ±15 rad/s。
因此合成输出不再保证 S 曲线的加速度/jerk 边界，力矩前馈仍保留原来的限幅与变化率保护。
此路径替代旧 Yaw 非对称斜坡，旧 `yaw_accel_limit_*`、`yaw_decel_limit`、
`yaw_release_limit`、`yaw_reverse_limit` 参数暂不参与试验控制。
失能或未就绪时重置 Yaw 规划与姿态目标，规划失败时提交安全目标并请求失能。
主机使用框架规划器验证：0→8 rad/s 约 74 ms、8→-8 约 128 ms、8→0 约 74 ms；
快速改目标及速度/加速度/jerk 边界检查通过。时间为规划输出结果，未测实机响应或 MCU 执行耗时。
原补偿后置版本曾用实际 `ControlYaw` 函数和框架规划器做主机检查：正负角速度阶跃、
小角速度补偿、合成限幅、摇杆反向、力矩前馈限幅与零状态恢复通过；未验证实车左偏改善。

### 云台 IMU Yaw 位置外环

反馈使用 `Gimbal_INS_State_Topic.yaw_rad`；回传协议见
[云台 INS 回传底盘](../../System/Transport/GIMBAL_IMU.md)。
电机位置反馈仍供底盘跟随与平移坐标旋转使用，不替换成绝对 IMU Yaw。

参数集中在 `Chassis_Config.h`：`yaw_position_kp=3`（1/s）、
`yaw_position_ki=0`（1/s²）、`yaw_position_kd=0`（无量纲）、
`yaw_position_speed_max_rad_s=0`、`yaw_imu_max_age_us=10000`。
这些增益是初始试验参数，尚未实机闭环调参。2026-10-06 保持底盘静止、手动转动
Yaw 轴，通过探针读取两组数据：电机角度增量约 +1.745 / +1.158 rad，
云台 IMU Yaw 对应增量约 +1.738 / +1.169 rad（均已处理回绕），方向一致。
`yaw_motor_to_imu_sign` 因此设为 **+1**；0 禁用 Yaw，-1 用于反向安装。
保留现有摇杆电机转向映射，不改 CH4 极性。此次为运动方向观测，尚未验证主动闭环。

令 `s` 为方向（±1）、`v` 为 S 曲线规划后的摇杆电机速度，2 ms 控制周期执行：

```text
首次就绪 / 恢复：target = 当前 imu_yaw
每周期：target = wrap(target + s * v * dt)
error = wrap(target - imu_yaw)                         // [-π, π] 最短路径
correction = PID(error, dt)                           // IMU rad/s，输出不单独限幅
motor_speed = clamp(v + s * (correction - gain * chassis_gyro_z), -15, +15)
SetMIT(0, motor_speed, 0, kd, torque_ff)
```

摇杆回中后，S 曲线减速到零，角目标随减速段继续积分，停稳后保持；外环复用 `Class_PID`，
目前 Kp=3、Ki=0、Kd=0，先以比例项调试；PID 输出与积分分量限幅均关闭（参数 0），Ki 仍为 0。
位置 PID 修正不单独限幅，摇杆前馈与 PID 修正合成后的电机速度仍限幅 ±15 rad/s。
`gain=yaw_rate_feedforward_gain`，默认 +1，假设底盘 BMI088 Z 轴与云台 IMU Yaw 正方向一致；
须实测底盘转动时两者符号，反向安装需设为 -1。前馈不经过摇杆规划，也不积分进地面系角目标。
不依赖云台 IMU 角速度字段。MIT Kp 恒为 0，Kd 形成电机编码器速度内环，
不能将 IMU 绝对角直接写入电机 MIT 位置字段。
使用本板 INS 角速度前馈，底盘转动由本板 BMI088 角速度前馈抵消，位置环修正剩余角度偏差。
云台 Yaw 或本板 BMI088 gyro_z 缺席 / 非有限 / 超过 10 ms 则请求
Yaw 失能。失能或电机未 ready 时每 1 ms 清除角目标、PID 积分与微分历史、速度规划、阻尼与力矩前馈历史，
不积累摇杆目标；再次 ready 后重新捕获当前姿态。四轮的输出许可仍由底盘命令决定。

主机检查使用实际 `Chassis_Update` / `ControlYaw` 与框架 `Class_Trajectory`，模拟
电机接口和时间源，分别验证方向 0 / +1 / -1：未标定禁止 Yaw 且不撤销四轮许可、
捕获与保持、角度接缝最短路径、正负方向纠偏、摇杆积分与减速停稳、速度 / 力矩前馈
限幅、10 ms 时效边界、非有限输入、未就绪与恢复、命令撤销。ChassisBoard 构建通过。
方向已通过两组手动转轴数据确认；尚未烧录方向 +1 的版本或验证主动闭环，仍须低速调参。

### 量纲约定

老步兵底盘三轴速度沿用实车验证过的抽象量纲（与麦轮预混后的 DM 轮速同量纲），没有可信
的 m/s 标定。输入仲裁按框架 SI 边界（`INPUT_MAX_TRANSLATION_M_S` /
`INPUT_MAX_ROTATION_RAD_S`）校验，因此：Input 侧用 `Chassis_*_ToSi` 归一化，
本模块用 `Chassis_*_FromSi` 还原，两者共用 `Chassis_Config.h` 中的同一份比例。
这是边界换算约定，不代表这些数值已经标定为 SI 物理量。

反馈按同一约定回写规划值（本板不测量真实车体速度）：`online` 表示四轮在线，
`enabled` 表示四轮 ready 且当前不是 `ZERO_FORCE`。Yaw 轴状态按 `GimbalFeedback`
发布（`yaw_rad` 为电机单圈角，`yaw_speed_rad_s` 为反馈速度，`ins_valid` 为云台回传 INS 新鲜），
输入层用它做平移坐标旋转与跟随判断，本板不拥有 Pitch。

## 安全与恢复

- CH5 < 0 时触发手动保护，复用遥控失联互锁：撤销 Remote 输入许可，RobotCmd
  发布底盘 `ZERO_FORCE`、Yaw `DISABLED`、Shoot `OFF` 并清除射击事件；板间按原有
  2 ms 周期转发零通道。CH5 ≥ 0 且链路持续健康 200 ms 后按原逻辑重新解锁。
  不改变 SBUS Device 的真实在线状态；此保护是软件许可，不切断动力电源。

- 上电默认失能：`Chassis_Init()` 先下发 Yaw 安全目标，再对全部已配置电机
  `RequestEnabled(false)`；即使部分电机注册失败也尝试停住它们。
- 使能请求是边沿语义，由框架 `Class_DMMotor` 与 100 Hz `StatusTask::ServiceAll`
  保证补发；应用不手写周期重发。
- 任一 Topic 过期、遥控失联或未解锁时，RobotCmd 立即发布 `ZERO_FORCE` 与 `DISABLED`，
  四轮与 Yaw 同周期停手。
- 输入层在链路失效或未解锁时向云台板转发零通道，避免云台板继续使用旧摇杆值。
- 状态灯：由控制诊断快照驱动颜色与闪烁次数，详见下方 WS2812 指南。

## 板间下行帧

三个帧都经框架 CAN BSP 的周期通道下发（同一 (总线, ID) 只保留最新值），
每 2 ms 刷新一次，与老工程 `GimbalTask` 周期一致。

| 帧 | 总线 | 布局 |
| --- | --- | --- |
| 0x065 | FDCAN2 | byte 0~1 火控开关、2~3 发射速度、4~5 Pitch 轴，大端 int16，已减中位；最小有效长度 6 |
| 0x070 | FDCAN2 | byte 0~1 Yaw 电机角度、2~3 地面系 Yaw，大端 int16，单位 0.01°，`(deg - 180) * 100` |
| 0x075 | FDCAN2 | byte 0~1 枪管热量上限、2~3 冷却值、byte 4 机器人 ID；裁判系统未接入时全 0 |

- 火控开关极性：实车与云台板约定相反，输入层转发前取反。
- 地面系 Yaw 没有独立陀螺仪来源，按老工程约定暂用 Yaw 电机角度代替。
- 云台板当前只解析 0x065；0x070/0x075 保持与老工程逐帧一致，便于后续接入。
- 下行无应答；云台另以 0x143/0x144 回传 INS，完整协议和读取接口见
  [云台 INS 回传底盘](../../System/Transport/GIMBAL_IMU.md)。收到 INS 不代表下行命令被确认。

## 与老工程（rm/demo）核对

`User/bsp/bsp_def.h`、`User/bsp/sbus_channel_bsp.c`、`User/algorithm/CHASSIS_ALG.c`、
`User/algorithm/SpeedPlanning.c`、`User/module/DM_drv.{c,h}`，以及云台板老工程
`H7_RM` 的 0x065 解码端。

已核对一致：

有意偏差（原因随列）：

- **火控开关取反**：老工程原样透传；云台板固件（老步兵云台分支）按 ≤-500 判为按下，
  而实车按下时原始通道为正，因此发送端必须取反，见输入层 `kFireSwitchInvert`。更换
  遥控器或改通道极性时必须与云台板一起复核。
- **失联立即失能**：老工程允许失联 200 ms 后才失能；本实现坏帧/失联即锁定（更严格）。
- **失联主动转发零通道**：老工程在拿不到 SBUS 帧时干脆不发 0x065；本实现按 2 ms 继续
  转发零通道，明确清掉云台板侧的旧摇杆值。
- **Yaw 反馈有效性门控**：老工程无条件用电机位置做坐标旋转；本实现要求 Yaw 轴反馈
  有效，避免反馈失效时算出接近 180° 的偏差把速度方向翻转（老工程已修过的实车故障）。
- **使能生命周期**：老工程在解锁时补发一次使能；本实现交给框架驱动的边沿请求与
  StatusTask 补交。
- **失能期间规划回零**：老工程继续维护规划状态、只靠发送门关闭输出；本实现让规划按
  释放减速度回零，重新使能时从零速起步。
- **控制量被反馈门控**：框架 `SetSpeed`/`SetMIT` 在电机未 ready（离线/未使能/故障）时
  只发零目标。老工程底盘四轮**从未解析过反馈**（`DM_Chassis_4Motor_Get` 无调用者，
  FDCAN1 回调只处理 Yaw 电机），属于开环下发；本实现因此新引入了“四轮反馈必须正常”
  的依赖，见下方待上板确认项。
- **0x070 编码**：老工程把弧度值直接减 180 再乘 100（rad/deg 混用）；本实现按
  rad → degree 在编码边界转换一次并夹到 int16 值域（与老步兵测试分支的修正一致）。
- **未迁移**：串口调试/JustFloat 遥测（老工程 `DebugTask`）、UART7 维特陀螺仪（老工程
  只用于调试打印）都不属于控制链，本板不接；0x070 的地面系 Yaw 仍是待接入项。

## 验证

- `cmake --preset ChassisBoard` 与本仓库三树（SingleBoard / GimbalBoard / ChassisBoard）
  从零构建通过，无新增告警。
- 未做实机验证：电机方向与 ID、Yaw 力矩方向与阻尼、麦轮正方向、云台跟随方向与增益、
  板间帧收发、失联失能时序都需要上板核对。
- 需上板确认的新依赖：四路底盘电机的反馈必须真正到达 FDCAN1 的 0x60~0x63（框架在
  反馈不可用时只发零目标），否则表现为“电机在线但轮子不动”；老工程没有这条依赖。
- 当前 S 曲线试验版改变了老工程的非对称规划策略，已检查主机规划边界，
  仍需实车确认快速反向与制动手感。

## 调试输出

底盘已关闭 RC、YAW 周期 RTT 文本日志，以及 Flash 初始化和 OSPI 回调的 RTT 文本输出。
设备在线检查、协议安全服务和 [100 Hz Flash 故障记录](FlashLog/README.md)保持启用。

## WS2812 状态灯

灯色、故障优先级、闪烁次数和验证范围见 [底盘 WS2812 指南](../../../docs/debug_ws2812_chassis.md)。Application/Diagnostics 负责诊断和灯效，Chassis 仅提供状态；ControlTask 调用诊断发布，TIM_1ms_Task 调用灯效刷新；灯效不修改控制许可。

### 2026-10-06 RTT 首轮试调

已有 340 条完整有效记录中，摇杆规划速度均为零，角度误差平均约 0.015 rad、
最大约 0.035 rad。筛选连续、目标稳定、低加速度片段后有 95 对样本，其中
94 对为负向底盘转动，正向仅 1 对，不足以可靠重标定双向前馈；
`yaw_rate_feedforward_gain` 保留 1.0。位置 Kp 从 2.0 试调到 3.0，Ki/Kd 保持零，
增强小误差修正；没有实测证明新参数已改善响应，仍需烧录后检查过冲、振荡与双向转动。
原始 RTT 存在断段和历史积压，不以整段统计值直接拟合动态模型或提高 I/D。
