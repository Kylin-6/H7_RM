## 老步兵配置移植到 H7_BSP（分支 `老步兵测试`，提交 `cb05beb`）

把 `~/code/project/rm/demo`（老步兵，单 `main` 分支，工作区 4 个文件未提交）的机器人
逻辑移植进 H7_BSP 的 Application 层，采用「就地改造 + 宏区分两套实现」方案。

### 关键架构事实

- 老步兵是**双板架构**：底盘板（本次移植目标）负责底盘电机、SBUS 遥控、姿态解算，
  并经 FDCAN2 用 `0x065/0x070/0x075` 把遥控与状态转发给独立的**云台板**；发射机构
  由云台板负责，底盘板不碰。
- 底盘板硬件：FDCAN1 挂 4 路 DM 速度模式底盘电机（节点 `0x50~0x53`，接收 ID
  `0x60~0x63`）+ 1 路 DM MIT 云台电机（节点 `0x03`，接收 ID `0x05`）；SBUS 走 UART5。
- 框架的 UART5 早已按 SBUS 参数配置（100000 / 9B / 偶校验 / 2 停止位 / 仅 RX，
  引脚宏 `SBUS_TX__UART_RX_Pin`，DMA2_Stream3），移植时无需改外设。

### 关键决策与坑

- **控制周期差异**：demo 是 2 ms，框架是 1 ms。速率限制的单位是「速度单位/秒」，
  所以把 `*_CONTROL_DT` 改成 `0.001f` 后每秒加减速特性与 demo 一致，无需改限制值。
- **DM 节点 ID 超范围**：`Class_DMMotor::Init` 原本限制 `can_id <= 0x0F`，而老步兵用
  `0x50~0x53`。已放宽到 `0xFF`，并把反馈匹配从 `data[0]&0x0F == can_id` 改为比较
  低 4 位（由 `master_id` 保证唯一性）。对原有 `0x00~0x0F` 配置行为不变。
- **C/C++ 链接**：框架的 `bsp_uart.h` 没有 `extern "C"`，C 文件调用 `UART_Init` 会
  链接失败，所以 `sbus` 用 `.cpp` 编译单元。
- **安全互锁的框架化**：demo 的 `SafetyTask`（整板使能门控）映射为「未解锁时每周期
  显式下发 `ZERO_FORCE` + `GimbalMode::DISABLED`」，而不是复刻整板门控。
- 原 `Chassis_Analysis_Vel` 会把轮速组合结果强转 `int16_t` 再赋回 `float`，本次保留
  浮点精度（已在文档标注差异）。

## 补充：用户追问"是否全部适配"后的核查（提交 `450d32d`）

### 补上的遗漏

- **WS2812 武装指示灯**：上轮只做了健康互锁状态，漏了驱动指示灯。demo 语义是
  「红灯 = 电机失能，蓝灯 = 已解锁」，在 `SafetyTask` 状态跳变时切换，上电默认红。
  已接入 `Communication::Communication_UpdateArmState`。框架内无其他模块争用灯色，
  所以只在状态变化时设置即可，不需要像 demo 的 `DebugTask` 那样每帧重申。

### 核查结论（重要，供后续参考）

- **FDCAN 两边等价**：demo 80MHz/PSC=1、框架 120MHz/PSC=3，位时间都是 1 Mbps、
  采样点都是 75%。`MessageRAMOffset` 与 `AutoRetransmission` 不同但不影响互通。
- **UART5 的 SBUS 参数两边完全一致**，底层不用动。
- **框架 BMI088 是 demo 的超集**：C++ 类化之外还修了两处（PRIMASK 恢复方式、
  `Init_Finished_Flag` 加 volatile）；但丢了 5 个 C 接口（`BMI088_Get_Yaw_Rate` 等），
  等价能力在 `sys_imu.cpp` 的 `System_IMU_Publish_State` 里。
- **`alg_basic` / `alg_filter_vqf` / `alg_matrix` / `alg_quaternion` / `bsp_spi`
  两边源码完全相同**，属同源抽取，无需移植。
- **demo 里的死代码**：`User/algorithm/PID.c` 无任何调用者；`Booster_Left/Right_ID`
  只有定义无引用；`bsp.h`/`device.h`/`bsp_def.c` 是空模板。都不要移植。
- **VQF 参数差异待定**：demo 用 `alg_filter_vqf.h` 里的默认值（`Rest_Threshold_Gyro_Deg_S
  = 2.0`），框架在 `System_IMU_Configure()` 里显式配成 3.5。阈值越大越容易判静止、
  零偏估计越激进。老步兵若要复现 demo 行为需改 `sys_imu.cpp`，但这是整机级参数，
  改动会影响所有配置，建议实车确认后再定。
- **未移植且判断为合理**：`DebugTask` 的遥测打印、`WitGyro`（含 `uart_bsp.c` 的 WIT
  DMA 分支）、`ElegantDebug` —— 三者在 demo 中都只服务于调试显示，不参与控制回路，
  且框架已有 `sys_debug` / EricTool 通道。
