## 框架评价（二轮：逐文件核实 + 实测）
本轮改为直接读源码并实测，发现上一轮未暴露的具体缺陷（未改任何代码）：
- `Core/Src/freertos.c` 的 `getRunTimeCounterValue()` 是 `__weak` 空桩恒返回 0，而 `Core/Inc/FreeRTOSConfig.h` 中 `configGENERATE_RUN_TIME_STATS=1` 且无人复写 → 运行时间统计/CPU 占用率全为假数据，与 CHANGELOG「后续计划 2：CPU 运行统计接入遥测」冲突。修法：用 DWT CYCCNT 实现，或关掉该宏。
- `CMakeLists.txt` 中 `H7_APP_GIMBAL/CHASSIS/SHOOT` 默认 OFF，而 `Control_Task.cpp` 无条件调用 `Gimbal_Update/Chassis_Update/Shoot_Update` → 按 README 的 `cmake --preset Debug` 构建出的固件不含任何机器人控制路径，且表现为静默空转。
- `configASSERT` 已定义（FreeRTOSConfig.h）但失效模式是 `taskDISABLE_INTERRUPTS(); for(;;);`，叠加无 IWDG → 断言触发即关中断静默锁死、无复位无痕迹。注意：验证方案 md 称「用户代码无 configASSERT」与实际不符。
- 三处清单腐化：`Application/Communication/Com.cpp` 未进 target_sources（仅有 include 路径，实为空函数）；`Application/Balance` 被列为 include 目录但目录不存在；`Tests/Shoot/` 为空目录。
- `InsTask`(8KB 栈) 与 `StorageTask`(4KB 栈) 创建后立即 `osThreadExit()`，仍占 64KB heap 峰值 12KB；DTCMRAM 已用 99372 B/128 KiB。
- 文档自相矛盾：验证方案 md 称 StatusTask「1 Hz CheckAll」，实际 `StatusTask.cpp` 是 100 Hz（10 tick），README 的 10 ms 说法才对。
- 实测结论（可复现）：7 套主机测试 19 项全部通过；`cmake --build --preset Debug` 无待编译工作即已最新。内存实测：DTCM 99372 B，.dma_buffer 20704/65536 B，.ram_d1_data 16384 B，FLASH text+rodata ≈121 KB/1 MB。
